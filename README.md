# zenon-faucet

Claim GLYPHS by locking PlasmaPoints in a Zenon HTLC, from a static page.

The user connects the [Syrius browser extension][syrius], locks `N × 1000` PP in
the `htlc` embedded contract, and the page settles both sides: it locks `N`
GLYPHS back to them under the same hashlock, releases the PP to the faucet, and
redeems the GLYPHS on their behalf. Four signed blocks, one preimage, no backend.

```
                 preimage P, hashlock H = sha256(P)   (generated by the page)

  1.  USER   htlc.Create   N×1000 PP  → hashLocked <faucet>          [Syrius]
  2.  page   htlc.Create   N GLYPHS   → hashLocked <user>            [page wallet]
  3.  page   htlc.Unlock   leg 1, revealing P  → pays <faucet>       [page wallet]
  4.  page   htlc.Unlock   leg 2, same P       → pays <user>         [page wallet]
  5.  user   receive block for the GLYPHS                            [Syrius]
  6.  page   receive block for the PP                                [page wallet]
```

`<faucet>` is not configured anywhere: it is the address derived from
`FAUCET_MNEMONIC`, the same wallet that pays the GLYPHS out. The two have to be
the same account — a faucet that charges PP into some *other* address is giving
its GLYPHS away, and if that address happens to be the claimant's own, step 3
hands the PP straight back and the swap costs them nothing.

## Why the page can settle both legs

`htlc.Unlock` may be called by **anyone**, and it pays `hashLocked` — the address
recorded in the entry, never the caller. From
`vm/embedded/implementation/htlc.go`:

```go
allowProxyUnlock, err := GetHtlcProxyUnlockStatus(context, htlcInfo.HashLocked)
// if proxy unlock is not allowed, only hashlocked can unlock
if !allowProxyUnlock && sendBlock.Address != htlcInfo.HashLocked {
    return nil, constants.ErrPermissionDenied
}
```

`GetHtlcProxyUnlockStatus` returns `true` when no record exists — "This defines
the default behavior to allow proxy unlocks". Everything else the contract checks
(not expired, `len(preimage) <= keyMaxSize`, hash matches) is caller-independent.
So a wallet holding nothing can settle a leg it is not a party to, which is what
makes steps 3 and 4 possible at all.

There are three states, not two: `Default`, `ExplicitDeny`, `ExplicitAllow`, and
once an address goes explicit it can never return to the default. If the
connected account has called `DenyProxyUnlock`, step 4 cannot be signed by the
page — so it builds the identical block and hands it to Syrius for the user to
sign instead. `hashLocked` is always permitted to unlock itself, so there is no
refusal path.

Step 3 is never in question: the faucet is `hashLocked` on leg 1 *and* the
account signing the unlock, and the check above only ever refuses a third party.
Only leg 2 has a payee the page does not control, so that is the only one whose
proxy status is read.

## What this is not

**The page holds the preimage the whole time.** It is the counterparty to the
swap and has to sign two blocks with nobody present, so its mnemonic is in the
bundle and anyone who loads the page has that key. Building from a secret and
obfuscating the result raises the effort to read it; it does not change this.
The HTLCs make each leg atomic and refundable; they do not remove the trust.
Treat the faucet wallet as holding exactly what the faucet is prepared to give
away — see [Deploying](#deploying).

The two expiries are chosen for what happens when something goes wrong:

| leg | expiry | who can reclaim | why |
|---|---|---|---|
| PP (user's) | 30 min | the user | their money sitting still, so it is the short one |
| GLYPHS (page's) | 60 min | the page | after step 3 the preimage is public and the user can unlock leg 2 out of the block that revealed it — this is how long they have to notice |

## Running it

The devnet must be up (`make devnet-up` in `go-zenon`), and both tokens must
exist on it. Neither exists on a fresh chain: a ZTS is derived from the hash of
the block that issued it, so devnet's PP is permanently a different token from
mainnet's.

```sh
npm install
npm run setup:devnet   # issues PP and GLYPHS, writes their ids to src/network.ts
npm run dev            # http://localhost:5180
```

`setup:devnet` is idempotent — a token this wallet already owns with the right
symbol is adopted rather than reissued. `make devnet-down-wipe` invalidates it.

On devnet the page shows a **Send me PP** control whenever the connected account
cannot cover the claim. That is not a feature; this build issues its own PP, so
the faucet wallet owns the entire supply and no other account has any, and
without it the Claim button can never be pressed.

### Checking it

```sh
npm run check    # tsc
npm run smoke    # the whole claim, against the running devnet
```

`smoke` drives a real claim end to end with no browser: the only substitution is
`signAsUser`, which signs the user's blocks with a local devnet key where the
extension would prompt. Everything downstream is the code the page runs, and the
assertions are read back off the ledger rather than out of the engine's own
return value. It also pins the three htlc ABI method ids against go-zenon's
encoder.

Last run: 20/20, both legs settled, `2` GLYPHS to the user and the `2000` PP
received into the faucet's own balance — `13216356 → 13218356`.

It takes several minutes, and the reason is worth knowing. The stand-in user is
devnet index 9, which has **no QSR fused**, so every block it publishes mines a
nonce at difficulty 31,500,000 — a minute or so each in JavaScript. That is not
the page's path (the faucet wallet has 21M plasma fused and reports
`requiredDifficulty: 0`, so it never mines), but it does mean `smoke` exercises
`znn/pow.ts` against a real node, which nothing else does. Fusing QSR to index 9
would make the run fast and silently stop testing that.

## Configuration

| where | what |
|---|---|
| `.env` | **the mnemonic**, and any chain overrides — gitignored, copied from `.env.example` |
| `src/network.ts` | chain id, node URL, the two token standards — defaults, **generated** by `setup:devnet` |
| `src/config.ts` | price, expiries, account index |

The mnemonic is not in the source. It is read from `FAUCET_MNEMONIC` and
substituted at build time — Vite's `define` for the bundle, `process.env` for
the scripts in `scripts/`, which read the same `.env` via
`node --env-file-if-exists`. A production build with it unset fails rather than
producing a bundle whose wallet cannot sign.

```sh
cp .env.example .env    # the devnet phrase: public, committed to go-zenon, worthless
```

Every field of `network` is overridable the same way, because the committed
defaults are a local devnet and a deployed page cannot use them — see below.

| variable | default |
|---|---|
| `FAUCET_MNEMONIC` | *none — required for a build* |
| `FAUCET_RPC_URL` | `http://localhost:35997` |
| `FAUCET_NETWORK_NAME` | `devnet` |
| `FAUCET_CHAIN_ID` | `69` |
| `FAUCET_PP_ZTS` / `FAUCET_GLYPHS_ZTS` | the ids `setup:devnet` wrote |
| `FAUCET_BASE_PATH` | `/` |
| `FAUCET_ACCOUNT_INDEX` | `3` — BIP-44 account index of `FAUCET_MNEMONIC` to sign with (`m/44'/73404'/index'`, same SLIP-0010 ed25519 derivation as znn_cli_dart and Syrius) |

For mainnet: set `FAUCET_RPC_URL` to a mainnet node, `FAUCET_CHAIN_ID=1`,
`FAUCET_PP_ZTS=zts1hz3ys62vnc8tdajnwrz6pp`, `FAUCET_GLYPHS_ZTS=zts1nrvf92dp6dg894g20glyph`
(both also exported as `MAINNET_PP_ZTS` / `MAINNET_GLYPHS_ZTS` in `src/network.ts`
for reference), and put a mnemonic in `FAUCET_MNEMONIC` whose account holds
only what you intend to hand out. Setting `FAUCET_NETWORK_NAME` to anything but
`devnet` also removes the PP control.

## Deploying

`.github/workflows/deploy.yml` builds on every push to `main` and publishes to
GitHub Pages. One-time setup:

1. **Settings → Pages → Source: GitHub Actions**
2. **Settings → Secrets and variables → Actions**
   - secret `FAUCET_MNEMONIC` — the faucet wallet's 24 words
   - variable `FAUCET_RPC_URL` — an `https://` or `wss://` node
   - variable `FAUCET_ACCOUNT_INDEX` — which account index to derive and sign with (optional, defaults to `3`)
   - variable `FAUCET_BASE_PATH` — set to `/` if you configure a **custom domain** (Settings → Pages → Custom domain); leave unset for the plain `https://<owner>.github.io/<repo>/` URL

The RPC variable is not optional in practice. Pages is served over HTTPS, and a
page on HTTPS may not call `http://localhost` — the browser blocks it as mixed
content before the request leaves. The workflow warns when it is unset.

The base-path variable matters as soon as a custom domain is involved: the
default (`/<repo>/`) is only correct for the bare `github.io` project-site URL.
A custom domain serves from the root, so with the default still in effect every
asset the page requests (`/…/assets/*.js`, `*.css`) 404s, the stylesheet never
loads, and the page renders as raw unstyled HTML — most visibly, the small
header logo becomes a giant unstyled shape covering the page.

### What the secret does and does not buy

Keeping the mnemonic in a secret keeps it **out of git**, which is the one place
a leak cannot be taken back: history is permanent, forks copy it, and scrapers
read it. Rotating the wallet becomes a secret change and a re-run rather than a
commit.

It does **not** make the mnemonic secret from users of the site. The built page
signs two blocks with no human present, so it ships the signing key to everyone
who loads it. That was true when the phrase was in `config.ts` and it is still
true now.

`npm run build` runs `scripts/obfuscate.ts` over the app chunk, and the workflow
refuses to deploy a `dist/` in which two consecutive mnemonic words appear as
readable text. Read that for what it is: the phrase stops being a contiguous
string in a public asset, which defeats the automated scraping that finds keys
by grepping for BIP-39 runs. It does not defeat a person with devtools, and
nothing that ships to a browser could.

So the account is what bounds the loss:

- fund the faucet wallet with a faucet's worth of GLYPH and nothing else
- give it no other role on any chain
- rotate it whenever you would rotate a published credential

Only our own `src/` is obfuscated. `three` and the dependency chunk are split
out and skipped — the latter carries @scure/bip39's 2048-word English list, and
encrypting a dictionary anyone can download costs about 90kB gzipped and
protects nothing. (Every individual word of any mnemonic therefore appears in
that chunk. That is the wordlist, not the key; what matters is that no ordered
run of two survives anywhere in `dist/`.)

```sh
npm run build       # tsc, vite build, then obfuscate + verify
npm run build:raw   # the same build with the obfuscation pass skipped, for debugging
```

## Layout

```
src/
  znn/           a small Zenon client -- no SDK, no wasm
    primitives   bytes, bech32 addresses and token standards, sha3
    abi          the embedded-contract ABI encoder (htlc, token, plasma)
    wallet       mnemonic -> SLIP-0010 ed25519 -> address
    block        account-block hash, signature, publish
    pow          go-zenon's proof-of-work, for an account with no fused plasma
    client       JSON-RPC, and the waits for confirmation
  wallet/syrius  the extension: connect, read, sign an arbitrary account block
  claim.ts       the state machine above
  bg.ts          the background
  main.ts        the DOM
scripts/
  devnet-setup   issues the two tokens
  smoke          the whole claim, headless
```

`src/znn` is hand-rolled rather than `znn-ts-sdk`, which wants webpack, node
polyfills, argon2 and ethers to sign an account block. Everything it needs is
five algorithms and one JSON-RPC method; the encodings are pinned to go-zenon's
own and verified against the running chain by `smoke`.

The one thing worth knowing if you touch `block.ts`: the account-block hash is a
consensus rule, and a field at the wrong width produces a hash the node
disagrees with. It reports that as a **bad signature**, which points at the key
rather than at the encoding.

## The background

A lattice of points with a slow swell crossing it — the Network of Momentum, with
momentum in it. One draw call, ~25k points, no libraries beyond three.js. It
pauses when the tab is hidden, renders a single frame under
`prefers-reduced-motion`, and if WebGL is unavailable the page simply keeps its
flat background.

The palette is Zenon's own, read out of the Syrius extension's stylesheets:
`#67E646` lime on `#141414`–`#2F2F2F` neutrals, `#446AEF` for anything secondary.

[syrius]: https://github.com/sol-znn/syrius-extension
